# 大阪名物キャッチ 完全再現プロンプト集（v9 相当）

公開デモ: https://stosakagame12414.z11.web.core.windows.net/

本ドキュメントは、これまでの全対話で出したリクエストを漏れなく統合したものです。
試行錯誤の過程で出した修正指示（暗い、余白が余る、文字が読みにくい、ヘッダーが見切れる、
矢印が不要、CORS の末尾スラッシュ 等）は、すべて **最初から満たすべき仕様** として本文に織り込んでいます。

3 段階に分けていますが、段階 1 だけでもゲームとして完結します。

| 段階 | 内容 | 成果物 |
|---|---|---|
| 1 | ゲーム本体（ルール、レイアウト、演出） | HTML 1 ファイル |
| 2 | ニックネーム、スコア保存、ランキング | HTML 1 ファイル |
| 3 | Azure Blob 配置とデプロイ自動化 | HTML + deploy.sh + 手順書 |

## 遊び方

1. 画面を指でスライド（PC は左右キー）してお皿を操作し、上から落ちてくる大阪名物をキャッチする。
2. 大阪名物をキャッチするとスコア加算、大阪以外の名物を取るとダメージ（HP 減少、コンボ消滅、減点）。
3. 連続キャッチでコンボが伸び、スコア倍率上昇（最大 4 倍）と HP 回復が発生する。
4. 「金のたこ焼き」（必殺アイテム）を取ると 15 秒間、落下物がすべて大阪名物になり、お皿も 2 倍に拡大する。
5. 制限時間 60 秒、または HP が 0 になった時点（KO）でゲーム終了。
6. リザルト画面で地域別の内訳やスコアの内訳、ランクを確認し、必要ならリトライやランキング確認を行う。

## 段階 1 プロンプト  ゲーム本体

```text
ブラウザで動作する単一 HTML ファイルのゲームを作成してください。
外部ライブラリは使わず、HTML、CSS、JavaScript のみで完結させてください。

■ ゲーム内容
大阪のたこ焼きなどの名物が上から落ちてくるので、お皿を動かしてキャッチするゲーム。

■ 基本ルール
- 制限時間は 1 分。
- 大阪の名物をキャッチするとスコア加算。
- 大阪以外の地域の名物を取るとダメージ。HP ゲージが減り、コンボは消滅、スコアも減点。
- HP は 100 から開始。0 になると強制終了（KO）。
- 大阪の名物を連続でキャッチすると HP が回復していく。コンボ数に応じて回復量が増える。
- コンボ数に応じてスコア倍率が上がる。最大 4 倍。
- 落下速度と出現頻度は時間経過とともに上昇させる。
- ハイスコアは localStorage にキャッシュして次回起動時も保持する。

■ 必殺アイテム
- 必殺技ボタンは設置しない。代わりに「必殺アイテム（金のたこ焼き）」が落ちてくる方式にする。
- 通常より遅い速度で落下させ、金色の脈動リング、回転アニメーション、着地点を示す光の柱を付ける。
- キャッチすると 15 秒間、落下物がすべて大阪名物になる。
  落下中の他地域の名物もその場で大阪名物に変換する。
- 同時にお皿のサイズが 2 倍になる。効果終了時になめらかに元へ戻す。
- 効果の発動は 1 ゲーム 1 回のみ。取り逃した場合は一定時間後に再出現させる。
- 出現待ち、落下中、発動中、使用済みの状態をヘッダーのバッジで表示する。

■ お皿（プレイヤー）
- 人物アイコンは置かず、お皿だけで表現する。
- 白い皿本体、色付きのフチ、内側の受け皿、光のハイライトで立体的に描く。
- 通常時の皿幅は画面幅の約 42 パーセントを基準として、そのさらに 70 パーセント程度の
  控えめなサイズにする。
- 操作は画面を指でスライド。PC では左右キーにも対応する。方向ボタンは画面に置かない。

■ レイアウト
- スマートフォンの縦持ちを前提とした縦長レイアウト。
- 表示領域は上下左右すべてレスポンシブにして、画面の余った領域が出ないようにする。
  キャンバスは固定サイズにせず、残りの領域を埋める可変サイズにする。
- devicePixelRatio に対応させ、高解像度端末でも輪郭がぼやけないようにする。
- 描画サイズは横基準、落下速度は縦基準でスケールを算出し、細長い画面でも破綻しないようにする。
- ヘッダーがブラウザによって見切れないようにする。
  height は 100dvh を使い、body は overflow hidden にしてページ自体をスクロールさせない。
  visualViewport の実寸を優先取得し、safe-area-inset も padding に適用する。
  読み込み後に複数回タイミングをずらして再計算し、アプリ内ブラウザのツールバー確定後にも追随させる。
  ResizeObserver でも監視する。
- 画面回転やリサイズ時も、お皿と落下物の相対位置を保持したまま追従させる。

■ ビジュアル
- 暗い配色は避け、明るく楽しい雰囲気にする。
- 背景は水色の空から黄色、オレンジへのグラデーション。
- 太陽、流れる雲、カラフルな三角フラッグ、通天閣風のタワー、パステルカラーの街並みを描く。
- 落下アイテムには光の輪を付ける。
- 品名の文字は読みやすいよう大きめの極太フォントにして、
  背後に半透明の白い角丸帯を敷き、白フチも付ける。
- 必殺アイテム発動中は背景を黄金色に変化させる。

■ ツッコミ演出
- 大阪以外の名物を取ってしまったとき、地域ごとのツッコミを表示する。
  例 : 京都なら「それ京都やないか」「今 京都やねん」「はんなりしすぎや」
- 小さな文字ポップではなく、画面全体に薄く大きく浮かぶアニメーションにする。
  - 描画順序は背景の直後、落下アイテムより奥。
  - 不透明度の上限は 0.3 程度に抑え、うっすら透ける程度にする。
  - フェードイン、イーズアウトでの拡大、ゆっくり上昇、フェードアウトを 2 秒弱で行う。
  - 文字サイズは画面幅から自動算出し、最大拡大時でも画面内に収まるようにする。
  - 白のにじみで背景から浮かせ、地域色の面と細い縁取りを重ねる。
  - 同時表示は 2 つまでとし、連続で取っても画面が文字で埋まらないようにする。
  - 傾きと縦位置にランダムなゆらぎを持たせる。

■ タイマー
- ヘッダーに円グラフ形式のタイマーを置き、残り時間を扇形で減算表示する。
- 残り 15 秒で赤に変化させる。

■ リザルト画面
- 終了後、地域別のドーナツチャートを表示する。
- セグメントのホバーでツールチップ、クリックまたは凡例クリックで地域別の内訳へドリルダウンする。
- 内訳には品目ごとの個数、割合バー、スコア寄与、被ダメージを表示する。
- KPI として、大阪率、他地域数、最大コンボ、残存 HP、総ダメージ、総回復量、
  取り逃した大阪名物、必殺アイテムの出現と取得を表示する。
- リトライボタンとタイトルへ戻る導線を置く。
- スコアに応じたランクを表示する。

■ 出力
- 単一の HTML ファイルとして出力し、ブラウザで開くだけで動くようにする。
- 実装後にヘッドレスで動作検証し、結果を報告してください。
```

## 段階 2 プロンプト  ニックネーム、スコア保存、ランキング

段階 1 の成果物に対して続けて指示します。

```text
作成したゲームに次の機能を追加してください。

■ タイトルの可読性改善
- タイトル文字が明るい背景に埋もれて読みにくいため、フォントデザインを修正する。
- グラデーションの切り抜き文字はやめ、単色塗りとステッカー風の多重白フチにする。
- text-shadow を多方向に重ねて白フチを作り、下に段差と柔らかい影を落として立体的に浮かせる。
- 背景に対するコントラスト比を WCAG AA 相当（4.5 対 1 以上）にする。
- 和文タイトルと英字サブタイトルで色を分ける。

■ ニックネーム登録
- 不特定多数がアクセスする前提にする。
- 起動時にキャッシュを確認し、すでにニックネームが登録済みであれば、
  そのニックネームで自動的にスタート画面へ進む。
- 未登録の場合はニックネーム登録画面を表示し、登録してから開始できるようにする。
- 注意書きとして「本名ではなくニックネームにしてね」「入力した名前とスコアは保存され、
  ランキングとして他の人にも表示されます」を常時表示する。
- ニックネームが既存のリストと衝突した場合、入力した時点で即座に
  「別のニックネームにしてね」と表示し、開始ボタンを無効にする。
- 判定は入力の都度リアルタイムに行う。前後空白の除去、大小文字、
  空白詰めなどの正規化を行い、表記ゆれも衝突として検出する。
- 文字数は 1 から 12 文字。記号 < > " ' & \ / は禁止する。
- 裏側のプレイヤー ID として UUID を自動発行し、名前を変更しても同一プレイヤーとして追跡する。
- スタート画面からニックネームを変更できる導線も置く。

■ ニックネームの候補提示
- サンプルのニックネームを 300 個用意しておく。重複なし、1 から 12 文字、禁止記号なしとする。
- そこからランダムに 5 件をボタンとして表示する。
- ボタンをクリックすると入力欄にその名前が自動入力（Fill）され、その場で判定が走る。
- 選択したボタンはハイライトする。
- 「別の候補」ボタンで何度でも引き直せるようにする。
- すでに使われている名前は候補から自動的に除外し、提案をそのまま押せば必ず登録できるようにする。
- 大阪らしい語感の名前にする。
  例 : こなもん帝王、ソースまみれ、二度づけ禁止、たこ焼き番長、なんでやねん、なにわの虎

■ 残存 HP のスコア反映
- 合計スコア = キャッチ得点 + 残存 HP × 25 + 完走ボーナス 500
- KO の場合は HP が 0 のため、HP ボーナスと完走ボーナスはいずれも 0 とする。
- リザルト画面にスコアの内訳を明示する。
- ランクの閾値を新しいスコアレンジに合わせて再調整する。

■ スコアの自動保存
- ゲーム終了時に、スコアをニックネームと裏側の ID とあわせて JSON ファイルへ自動保存する。
- 保存先は Azure Blob Storage。パスは scores/{playerId}.json とし、
  プレイヤー 1 人につき 1 ファイルにする。
- 保存内容はベストスコア、プレイ回数、直近の詳細記録、プレイ履歴。
  詳細記録にはキャッチ得点、HP ボーナス、残存 HP、完走ボーナス、ランク、結果種別、
  最大コンボ、地域別集計、プレイ日時、ゲームバージョンを含める。
- 保存の成否をリザルト画面に表示し、失敗時は再送キューに積んで次回起動時に自動リトライする。
- SAS を設定していない場合は localStorage のみで動作させ、その旨を明示する。

■ ランキング機能
- ホーム画面で、ユーザー名が設定されているときに「ランキングを見る」ボタンを表示する。
- あわせて自分の現在順位をテキストでも表示する。
- ゲーム終了時にも順位を表示し、「ランキングを見る」ボタンを置く。
  ランキングから戻ったときはリザルト画面に復帰させる。
- ランキング画面には金銀銅のメダル、行の色分け、自分の行のハイライトと YOU バッジを付ける。
- 同点は同順位として扱い、次の順位を正しく飛ばす（15 位が 2 名なら次は 17 位）。
- リザルト内の上位表示で自分が圏外の場合は、区切り記号の下に自分の行を追加表示する。

■ 今日と全体のタブ切り替え
- ランキングを「今日のランキング」と「全体ランキング」に分け、タブで切り替える。
- デフォルトは「今日のランキング」にする。
- 今日はその日のベストスコア、全体は通算ベストスコアで集計する。
- タブに参加人数を併記する。
- 日付の境界判定は日本時間（UTC+9）で固定し、端末のタイムゾーン設定に影響されないようにする。
  タイムゾーンは設定値で変更できるようにする。
- 今日ランキングでは、その日に複数回プレイした人にプレイ回数を併記する。

■ 既に溜まっているログの再利用
- すでに公開してスコアの JSON が溜まっている前提とする。
- 既存の JSON を一切変換せず、そのまま読み込んで再集計できるようにする。
- 読み込み時に正規化して、次の旧形式すべてに対応する。
  - history 配列があり各エントリに playedAt がある形式
  - history がなく latest のみの形式
  - bestScore と updatedAt しかない形式
  - 日時情報が一切ない形式（全体ランキングにのみ参加させ、今日からは除外する）
  - history の最高値が bestScore より高い場合は bestScore を自動補正する
  - 壊れた JSON は静かにスキップする
- 保存時も既存の history を保持したまま追記する。既存キーは維持し、
  集計を速くするための補助情報のみを追加する。古い形式のままの端末が混在しても動作させる。

■ ページ送り
- 投稿者が多くなってきたため、ランキングはページ送りにする。
- 1 ページあたりの件数は設定値で変更できるようにする。
- 先頭、前、次、最終のボタンを置き、端では自動的に無効化する。
- 「自分の順位へ」ボタンを置き、自分がいるページへ一発でジャンプできるようにする。
- ランキングを開いた時点で自分のページを自動表示する。
- タブごとにページ位置を独立して保持する。
- PC では左右キーでもページ送りでき、Esc で閉じられるようにする。
- 1 ページに収まる場合はページャーを非表示にする。
- Blob の一覧取得は NextMarker を辿り、件数が増えても取りこぼさないようにする。

■ 出力
- 単一 HTML ファイル。
- 実装後にヘッドレスで動作検証し、結果を報告してください。
```

## 段階 3 プロンプト  Azure Blob 配置とデプロイ自動化

```text
作成したゲームを Azure Blob Storage に配置します。次を作成してください。

■ 構成
- Azure Storage の静的 Web サイトホスティングとコンテナー SAS を使う
  サーバーレス構成にする。
- HTML の先頭に設定ブロックを置き、SAS の URL だけ差し替えれば動くようにする。

■ deploy.sh
- Azure Cloud Shell で実行する前提のシェルスクリプトを作成する。
- 次を自動実行する。
  1. ファイルの存在確認。無ければ理由を表示して停止する。
  2. Azure へのサインイン確認とストレージアカウントの存在確認。
  3. キーと静的 Web サイトのエンドポイント取得。
  4. 静的 Web サイトの有効化。インデックスと 404 の両方に index.html を指定する。
  5. スコア用コンテナーの確認と、既存レコード件数の表示。
  6. SAS の発行（権限は racwl）。
  7. HTML への SAS 自動埋め込み。
  8. CORS の設定。
  9. index.html という名前でのアップロード。
  10. HTTP ステータスによる疎通確認。
- 既存のスコア JSON は絶対に削除しない。実行時に件数を表示して引き継ぎを明示する。
- リソースグループ名やアカウント名は環境変数で上書きできるようにする。
- 末尾に、今日と全体それぞれの集計用 jq コマンドを出力する。

■ 実装上の注意（必ず守ること）
- アップロード時は -n index.html でリネームする。
  元のファイル名のまま置くとルート URL では見つからず 404 になる。
- CORS のオリジンは末尾スラッシュを付けない。
  ブラウザーが送る Origin ヘッダーと完全一致が必要で、付けると保存が失敗する。
- 静的 Web サイトの URL は blob エンドポイントではなく web エンドポイントである点を明記する。
- インデックス ドキュメント名の前後に空白が入ると 404 になる点も手順書に記載する。
- Content-Type は text/html; charset=utf-8 を指定し、キャッシュ無効化ヘッダーも付ける。

■ 手順書
- ストレージアカウント作成、静的 Web サイト有効化、コンテナー作成、CORS 設定、
  SAS 発行、集計コマンド、セキュリティ上の注意を含める。
- SAS がクライアントに露出する点と、堅くする場合の Azure Functions 構成にも触れる。
- 404 WebContentNotFound が出た場合の原因と対処をトラブルシューティングとしてまとめる。

■ 出力
- 単一 HTML ファイル、deploy.sh、配置手順書の 3 点。
```

### 保存 JSON の構造

## 検証項目

プロンプトに含めておくと品質が安定します。

### ゲーム

- 必殺アイテム発動中に非大阪アイテムが 0 件であること
- 皿が発動時に 2 倍、終了時に元へ戻ること
- 必殺効果が 1 ゲーム 1 回のみで再発動しないこと
- 時間切れと KO の分岐でスコア計算が変わること（KO は HP ボーナスと完走ボーナスが 0）
- リトライ時に状態が完全リセットされること
- 複数解像度でレイアウトが破綻せず、皿が画面内に収まること
  （360x560、390x844、414x896、768x1024）
- 画面回転時に相対位置が保持されること

### ランキング

- 旧形式 4 パターンの JSON が正しく解釈されること
- 壊れたレコードがスキップされること
- history の最高値による bestScore の自動補正が効くこと
- 今日と全体で 1 位が入れ替わるケースが正しく処理されること
- 同点が同順位になり、次の順位が正しく飛ぶこと
- タブごとにページ位置が独立保持されること
- 「自分へ」ジャンプが正しいページを開くこと
- 1 ページに収まる場合にページャーが非表示になること
- JST の日跨ぎ（15:00 UTC）で日付キーが切り替わること
- 500 件規模でもページングが高速に動作すること

### ニックネーム

- 空、13 文字以上、禁止記号、既存との衝突がすべて弾かれること
- 前後空白などの表記ゆれも衝突として検出されること
- 候補 5 件から使用済みの名前が除外されること
- 候補クリックで入力欄に Fill され、即座に判定が走ること
- 再抽選で毎回異なる組合せになること

## 進め方のコツ

- 段階 1 だけでもゲームとして完結します。イベント規模やランキング要否に応じて
  段階 2 以降を判断してください。
- レイアウト調整は実機確認後の微調整が発生しやすい項目です。
  段階 1 の時点で対象端末とブラウザ（Safari、Chrome、LINE や X のアプリ内ブラウザなど）を
  伝えると手戻りが減ります。
- 検証項目をプロンプトに含めると品質が安定します。
- イベント別に名物やツッコミ文言を差し替えたバリエーション（名古屋版、博多版など）にも
  そのまま流用できます。データ配列と地域名を入れ替えるだけです。
